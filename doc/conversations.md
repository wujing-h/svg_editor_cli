## 004：局部恢复与图形树不变量

### 我的 prompt

> 理解了，command主要抽象命令，通过统一的命令执行接口来结构模块，composite保证调用命令相同，不随图形种类改变，工厂负责创建图形类，撤销我选择局部恢复，图形树维护不变量这点我不理解，要维护什么

### 你的回答

回答摘要：不变量是任何成功操作后都必须成立的结构规则：id 全文档唯一且大小写敏感；活动节点只有一个归属；父引用与子列表一致；树无循环；只有根和容器拥有子节点；同级顺序稳定；id 索引与实际树一致。失败操作还必须保持原状态。结构变化由领域文档的受控操作完成，命令不能直接改裸数组。局部恢复保存受影响的几何值、属性存在性、子树及原父节点和位置，避免整文档快照。

### 采纳或者不采纳

用户明确选择局部恢复，随后回复“没问题，我觉得合理”，要求形成职责划分与架构图供审查。

### 修改

`modules/domain.md` 列出树不变量；`modules/application.md` 列出各命令的局部恢复记录及“先校验、再应用、成功后更新历史”的流程。

### 总结

Command 负责一次操作及恢复记录，Composite 负责多态行为，文档负责树结构一致性；捕获错误本身不能保证失败原子性。

## 007：分组位置与保存路径语义

### 我的 prompt

> 我也觉得合理。还剩group相关的和save的我没有理解，其他按你推荐的来我觉得就可以

### 你的回答

回答摘要：group 将新组追加到所选成员父容器的最近公共祖先，成员保持分组前文档遍历顺序，不按参数顺序重排；旧容器变空后仍保留。跨父容器分组可能改变样式继承和组内外遮挡关系。save 的关联路径在成功 read 或显式 save 后更新；无参数 save 使用关联路径；init 后没有路径，首次保存需文件名；失败不改变关联。组自身 set fill/stroke 使用 SVG 继承，不覆盖子图形显式样式。

### 采纳或者不采纳

用户下一条明确“没问题，架构通过”，批准包含这些解释的方案。外部 SVG 的 transform、未知元素与额外属性仍需在 read 实现前明确。

### 修改

分组、顺序与样式语义放入 `modules/domain.md`；路径与读取边界放入 `modules/infrastructure.md`；历史协调放入 `modules/application.md`。

### 总结

课程未完全指定的行为应先公开讨论并写入架构；分组不承诺跨容器的全部视觉关系保持不变，保存路径只在成功后更新。
